4.2   Architectural Layer Description

This section provides a detailed description of the system architecture of the Puntland Prison Management System (PPMS). The architecture follows a classic multi-tier design pattern, structuring the application into six distinct layers, each with well-defined responsibilities and boundaries. This separation of concerns ensures maintainability, scalability, and security of the system.

The PPMS architecture is designed as a 5-Tier Web Application built on the ASP.NET Core 10 MVC framework. The system separates concerns across clearly defined layers, from the end-user interface down to persistent data storage and cloud deployment infrastructure. Layer 1
Client / User Layer

The Client Layer represents the external users and devices that interact with the PPMS through a standard web browser. No software installation is required on the client side; all interaction occurs through a web interface accessible via any modern browser such as Google Chrome, Microsoft Edge, or Mozilla Firefox. The system supports access from desktop computers, laptops, and mobile devices, as the user interface is fully responsive using Bootstrap 5.3.

The system defines three distinct user roles, each with different levels of access and permission:

  • Super Administrator: Has full system access including user management, system configuration, access to all reports and dashboards across all prisons, and the ability to create or deactivate other user accounts.
  • Prison Administrator: Has operational control over a specific prison facility, including managing prisoner records, staff information, security alerts, wanted criminals, case reports, and generating Excel reports.
  • Staff User: Has limited, read-oriented access, primarily for searching prisoner records, submitting alerts, and viewing assigned case information within their assigned prison.

All client requests are transmitted over HTTPS to the server, ensuring encrypted and secure communication at all times.

Layer 2
Presentation Layer

The Presentation Layer is responsible for rendering the user interface and delivering an interactive, visually consistent experience to the end user. This layer is implemented using Razor View Engine (.cshtml), which allows dynamic HTML generation on the server side by embedding C# code within HTML templates. All views are rendered server-side and sent to the client as complete HTML responses.

The Presentation Layer consists of the following key components:

  • Razor Views (.cshtml): Each functional area of PPMS — Dashboard, Prisoners, Staff, Prisons, Security, Case Reports, Reports — has a dedicated set of Razor View files that define the HTML structure and dynamic data display.
  • Shared Layout (_Layout.cshtml): A master layout template provides the consistent sidebar navigation, top bar, notification area, and page structure used across all views. The layout includes a dark navy enterprise theme with glassmorphism card styling and an animated canvas background.
  • Bootstrap 5.3: The Bootstrap CSS framework provides a responsive grid system, pre-built UI components (modals, buttons, forms, tables, dropdowns), and utility classes for rapid, consistent interface development across all screen sizes.
  • Chart.js 4.4.0: Used to render interactive bar charts, doughnut charts, and line charts on the main dashboard, visualizing prisoner statistics, case report trends, and crime type distributions.
  • Font Awesome 6.5: Provides a comprehensive icon library used throughout the interface for navigation icons, action buttons, and status indicators.
  • jQuery 3.7 & Select2: jQuery provides DOM manipulation and AJAX support; Select2 enhances dropdown select elements with search functionality.
Layer 3
Application / Services Layer

The Application Layer contains the core business logic and request-handling mechanisms of PPMS. It is built using the Model-View-Controller (MVC) design pattern provided by ASP.NET Core 10. This layer receives HTTP requests from the Presentation Layer, applies business rules, interacts with the Data Access Layer, and returns appropriate responses.

4.2.3.1   MVC Controllers

PPMS implements eight controllers, each responsible for a specific functional area of the system. The controllers handle HTTP GET and POST requests, apply authorization checks, invoke data operations through the AppDbContext, and return View results with the appropriate ViewModel data.

  • HomeController: Manages the main dashboard, aggregating statistics (total prisoners, staff, prisons, alerts) and chart data for display.
  • PrisonerController: Handles CRUD operations for prisoner records including registration, search, status updates, photo upload, and soft-delete (IsArchived flag).
  • StaffController: Manages staff records including hiring, assignment to prisons, status management, and staff search.
  • PrisonController: Manages prison facility records including capacity, location, type, and director information.
  • SecurityController: Handles alerts (creation, resolution, priority) and wanted criminal records including risk level and reward information.
  • CaseReportController: Manages case reports with auto-generated Case IDs in the format CASE-YYYY-NNNN, crime categorization, and analytics.
  • ReportController: Generates and exports Excel reports (.xlsx) using ClosedXML 0.104.2 for prisoners, staff, security, and case data.
  • AccountController: Handles user login, logout, profile management, and password operations.
4.2.3.2   Authentication & Role-Based Access Control (RBAC)

PPMS uses ASP.NET Identity to manage user authentication and authorization. All passwords are securely hashed using BCrypt before storage. Authentication is session-based using encrypted cookies. Authorization is enforced using the [Authorize(Roles = "...")] attribute on controller actions, ensuring each user can only access functions permitted by their assigned role. The three roles — SuperAdmin, PrisonAdministrator, and StaffUser — define a clear access hierarchy throughout the system.

4.2.3.3   Core Business Services
  • Prisoner Management Service: Enforces auto Case ID generation, manages photo file uploads to wwwroot/uploads, and applies soft-delete logic using the IsArchived boolean flag instead of permanent deletion.
  • Report Generation Service (ClosedXML): Dynamically builds Excel workbooks from live database data, formats columns and headers, and saves the output file to the server's file system for download.
  • Former Prisoner Service: Handles the archival process for released, pardoned, or transferred prisoners, moving them from the active prisoner table to the FormerPrisoners archive.
Layer 4
Data Access Layer — Entity Framework Core

The Data Access Layer (DAL) acts as an abstraction between the Application Layer and the physical database. PPMS uses Entity Framework Core 9.0.5, a modern Object-Relational Mapper (ORM), to interact with the SQL Server database. This eliminates the need for hand-written SQL in most scenarios and allows the application to work with the database using standard C# objects and LINQ queries.

  • AppDbContext: The central database context class that inherits from IdentityDbContext. It exposes all entity sets (DbSet<T>) representing the 15 database tables and serves as the entry point for all data operations.
  • Code-First Migrations: The database schema is defined entirely in C# model classes. EF Core migrations track schema changes and apply them automatically on application startup using db.Database.Migrate() in Program.cs, eliminating manual database setup.
  • LINQ Queries: All data retrieval uses Language Integrated Query (LINQ), supporting filtering, sorting, pagination, and eager loading of related entities using the .Include() method.
  • Change Tracking: EF Core automatically tracks changes to entity objects in memory, applying only the necessary INSERT, UPDATE, or DELETE operations when SaveChangesAsync() is called.
  • Seed Data: Migrations include seed logic to create default roles (SuperAdmin, PrisonAdministrator, StaffUser) and an initial Super Administrator account on first deployment.
Layer 5
Database Layer — SQL Server / PPMS_DB

The Database Layer provides persistent storage for all PPMS data. The system uses Microsoft SQL Server as the relational database management system (RDBMS), accessed through the connection string targeting (localdb)\MSSQLLocalDB in the development environment and a full SQL Server instance in production on Railway Cloud. The database is named PPMS_DB and contains 15 tables.

The following table summarizes the key database tables, their purpose, and primary fields:

Table NamePurposeKey Fields
PrisonersStores all active prisoner recordsPrisonerId, FullName, NationalId, CrimeType, Sentence, Status, IsArchived, PhotoPath, PrisonId
StaffStores prison staff recordsStaffId, FullName, Position, Department, HireDate, Status, PrisonId
PrisonsStores prison facility informationPrisonId, Name, Location, Capacity, Type, Director, EstablishedDate
AlertsStores security alerts and incidentsAlertId, Title, Message, AlertType, Priority, IsResolved, CreatedAt, PrisonId
WantedCriminalsTracks wanted criminal profilesWantedId, FullName, CrimeType, DangerLevel, Status, PhotoPath, Reward
CaseReportsStores criminal case recordsCaseId, CaseNumber (CASE-YYYY-NNNN), CrimeType, Status, Description, PrisonerId
FormerPrisonersArchive of released/pardoned prisonersFormerId, FullName, ReleaseDate, Reason (Released/Pardoned/Transferred)
ActivityLogsAudit trail for all system actionsLogId, UserId, Action, Entity, Details, Timestamp, IpAddress
AspNetUsersASP.NET Identity user accountsId, UserName, Email, PasswordHash, FullName, PrisonId, LastLogin
AspNetRolesSystem roles for RBACSuperAdmin, PrisonAdministrator, StaffUser

All tables use integer or GUID primary keys, foreign key constraints to enforce referential integrity, and appropriate indexes on frequently searched columns such as FullName, NationalId, and Status. The soft-delete pattern (IsArchived) is applied to the Prisoners table to preserve historical data without hard deletion.

Layer 6
Infrastructure & Deployment Layer

The Infrastructure Layer covers the hosting environment, deployment pipeline, and development tools used to build and operate the PPMS system. This layer sits outside the application code itself but is essential for the system's availability, continuous delivery, and maintainability.

  • Railway Cloud Platform: PPMS is deployed on Railway, a Platform-as-a-Service (PaaS) cloud provider. Railway handles server provisioning, automatic HTTPS, environment variable management, and zero-downtime deployments. The application listens on port 8080 in the production environment.
  • GitHub (Version Control & CI/CD): The source code is maintained in a GitHub repository at github.com/muhudiin23/PPMS on the main branch. Railway is integrated with GitHub to automatically trigger a new deployment whenever code is pushed to the main branch, implementing a basic Continuous Deployment (CD) pipeline.
  • Visual Studio 2022 (Development Environment): The system is developed using Visual Studio 2022 on Windows, with the application running on ports 7116 (HTTPS) and 5073 (HTTP) during local development. The local SQL Server instance uses (localdb)\MSSQLLocalDB.
  • NuGet Package Manager: All third-party dependencies (Entity Framework Core, ClosedXML, ASP.NET Identity, Bootstrap) are managed via NuGet and declared in the project's .csproj file for reproducible builds.
4.2.7   Layer Summary

The following table provides a concise summary of all architectural layers, their primary technologies, and their responsibilities within the PPMS system:

#LayerTechnologyResponsibility
1 Client Layer Web Browser (Chrome, Edge, Firefox) End-user interface access via HTTPS; three roles: SuperAdmin, Prison Admin, Staff
2 Presentation Layer Razor Views, Bootstrap 5.3, Chart.js 4.4, Font Awesome 6.5 Server-side HTML rendering, responsive UI, interactive charts, dark theme
3 Application Layer ASP.NET Core 10 MVC, ASP.NET Identity, ClosedXML Request routing, RBAC authentication, business rules, Excel report generation
4 Data Access Layer Entity Framework Core 9.0.5, AppDbContext, LINQ ORM-based database operations, migrations, change tracking, query optimization
5 Database Layer SQL Server, PPMS_DB Persistent relational data storage; 15 tables with referential integrity
6 Infrastructure Layer Railway Cloud, GitHub, Visual Studio 2022 Cloud hosting, CI/CD deployment pipeline, version control, development environment

The layered architecture of PPMS ensures that each component of the system has a single, well-defined responsibility. Changes to one layer — such as updating the user interface or switching the database — can be made with minimal impact on other layers. This separation of concerns is a fundamental principle of robust software engineering and makes the PPMS system maintainable, testable, and scalable for future enhancements.
